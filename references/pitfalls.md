# 跨项目通用坑（踩过的才写）

## 环境
- **后端没起就跑全量** → 几十条全 fail 白跑。先 curl 探活，任一不通就停。
- Playwright 装错目录（子目录），自己找 package.json。
- 本机有 Chrome/Edge 就用 channel，不下载内置浏览器。
- package.json type:module 决定 ESM/CJS。

## 选择器
- 别猜 class，读模板。`.option-item` 不存在，实际 `.opt`。
- 后代选择器 vs 连写要看 DOM。
- 异步渲染先 waitForSelector。

## 接口
- **正反用例成对打**：做对+做错、全对/全错/混合，不只测反面。
- 判成功要看数据：接口 completed 不等于真成功（空题假成功）。
- 前后端路径要对一遍。

## 功能覆盖
- **按钮级清单**：每个页面每个按钮都列，漏一个=漏测（改名/删除/重做）。
- **读 Service 层**：判分归一、慢题、阈值，不只看 Controller 路径。
- **测试脚本跟产品走**：路由改了脚本必须更新（/favorites→/collections）。
- **路由孤岛（踩过实锤）**：路由注册了、组件写好了，但全站没有任何按钮/菜单能点进去，用户只能手输 URL 访问。不崩溃、不报错，最容易漏。
  - 为什么 goto 式测试抓不到：所有 spec 都 `page.goto('/xxx')` 直接进页面，绕过 UI 入口，入口缺失对测试完全不可见。
  - 实例：智复习新版 `/profile`（ProfileView，含错因统计/今日复习菜单）零 UI 入口，首页【我的】按钮 `goProfile()` 仍跳旧版 `/user-center`；20 个 spec 全用 goto，整轮 28 passed 也漏判。
  - 防法：阶段 1 做「路由×入口」grep 交叉对照表（`router.push`/`to=` 反查每个路由）；阶段 4 每个路由配「从首页点击进入 + 断言 URL + 断言页面特征元素」的可达性用例；goto 只许用于造状态，不替代点击路径。
  - 新旧页面并存也是同类坑：入口指向的路由要核对是不是废弃旧页。

## 非功能
- 并行/多线程：用户设计目的，主动测，别当"代码读过了"就跳过。
- 网络异常/空态/快速操作。

## 执行
- 串行跑。
- trace 全程。
- 报告固定写项目根，不丢。
